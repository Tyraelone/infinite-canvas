# 本机共享画布、素材迁移与视频超分

用户已明确要求直接修改、迁移现有数据并验证，不再增加方案确认。

## 目标

在本机运行模式下，画布、素材库和关联媒体由 Go 后端统一保存到 D 盘；不同浏览器打开同一画布 ID 能看见同一内容。当前内置浏览器的数据须完整迁入，包含节点、连线、对话、图片、视频和素材清单。视频设置显示生成后 2× 超分，并提供已有 H3 视频的 2× 超分入口。

## 方案与边界

使用现有 Go/Gin/GORM 后端，SQLite 保留元数据和状态版本，媒体按 SHA256 内容地址存入 `data/workspace/files`，迁移原始快照写入 `data/workspace/migrations`。前端使用现有本机同源代理 `/api/local-runtime/workspace` 转发到 Go `/api/local-workspace`；仅本机运行模式启用，服务端校验本机接口 Token。Python 网关继续负责推理和视频超分。

不用按浏览器保存完整业务状态作为唯一来源，也不依赖登录或云对象存储。保留原始浏览器数据作为迁移备份，不读取或复制 AI 密钥、账号密码等配置。

## 存储契约

- 共享状态只有 `canvas` 与 `assets`，值为原 Zustand 持久化 JSON 字符串；GET 返回 `{value, revision}`，PUT 接收 `{value, revision}`，版本不匹配返回 HTTP409，禁止旧页面覆盖新内容。
- 文件原始 storageKey 保持不变，存储键只作为索引，不拼接磁盘路径；POST/GET/HEAD `/files/{encodedKey}` 上传或读取原始字节，GET 支持 Range，响应包含 SHA256、大小和类型。相同键内容不同须拒绝覆盖。
- POST `/import` 接收 `{migrationId, states, files:[{key,sha256}]}`，事务内核对所有文件和关联引用后合并状态。现存 ID 以服务器内容为准，仅导入缺失 ID；保留导入原始快照和报告。重复 migrationId 返回原报告，失败不发布部分状态，原始数据不删除。
- PUT 删除的实体记录墓碑，防止另一浏览器的旧副本在首次迁移时复活已删除内容。
- 前端所有共享读取、写入、媒体查找都等待一次自动迁移；保留一个浏览器本地缓存用于恢复，但本机服务写入失败必须可见，不能显示“已保存”后仅写浏览器。
- 不进行共享媒体的自动物理回收，避免某浏览器缓存不全而误删其他画布文件。

## 超分契约

复用影格已有 H3 / 2× 超分流程及其时长和显存限制。生成选项传给实际工作流；已有视频超分创建独立结果节点，保留原片。校验实际输出分辨率、帧数和音频，不能只看模型或接口注册成功。

## 验收

迁移前后画布 ID、节点、连线、素材数量和媒体 SHA256 相同；清空的独立浏览器读取同一画布并播放媒体；跨浏览器编辑刷新可见；重启后保留；旧版本写入被拒绝。新增 SR 入口可见，真实输出宽高翻倍且帧数/音频保留。
